## 1. Контекст: что такое MDGram

- **MDGram** — неофициальный Android-клиент Telegram с Material Design (автор **Richar Correa**, каналы @MDMods_You / @MDGramClub, сайт mdgram.app — мёртв, rcmods-apps.xyz — мёртв 404).

- **Пользователь** — энтузиаст, хочет вернуть проект к жизни «под новый ТГ», для личного использования.

## 6. Воспроизведение окружения (команды)

### 6.1 Если декомпилированный код потерян — восстановить заново (~40 мин)
```bash
mkdir -p /home/user/.cache/mdgram && cd /home/user/.cache/mdgram
curl -sL -o apk.apk "https://github.com/MDGramYou/MDGramYou/releases/download/v15.5/MDGramV15.5.apk"
curl -sL -o apktool.jar "https://github.com/iBotPeaches/Apktool/releases/download/v2.9.3/apktool_2.9.3.jar"
java -Xmx1200m -jar apktool.jar d -f -o res_out apk.apk          # ресурсы+smali (~15 с)
curl -sL -o jadx.zip "https://github.com/skylot/jadx/releases/download/v1.4.7/jadx-1.4.7.zip" && unzip -q jadx.zip
JADX_OPTS="-Xmx1300m" bin/jadx -d jadx_out --no-res --threads-count 2 apk.apk   # Java (~35 мин)
```
### 6.2 Среды сборки (для свежей базы Telegram)
- **Память песочницы:** 2 vCPU / 1.9 ГБ RAM / ~20 ГБ диск / Java 11 (системная; JDK 17 — качать Adoptium/Temurin). Полноценный AGP-сбор Telegram обычно требует 8–16 ГБ → здесь рискованно; помочь может swap-файл и лимиты Gradle (`org.gradle.jvmargs=-Xmx1536m`, `--max-workers=1`), но не гарантировано.
- **SDK/NDK:** командные инструменты Android (cmdline-tools) + platform + build-tools + NDK (всё умещается в 20 ГБ).
- Официальная инструкция сборки: в README DrKLO/Telegram (`sdkmanager`, JDK, `./gradlew :TMessagesProj_AppStandalone:assembleAfatStandalone -PabiSplits` у форков типа NekoX/jair1c).
- **Рекомендуемый путь к APK — GitHub Actions**: workflow на `ubuntu-latest` (есть готовые примеры у NekoX/Cherrygram/OctoGram) ставит JDK17+SDK+NDK и собирает; артефакт — APK.

## 7. GitHub: как подключить (у меня НЕТ кнопки/токена сам по себе)

Я не могу запросить OAuth-доступ к GitHub пользователя — такого инструмента нет. Реальные варианты:
1. **Пользователь создаёт репозиторий** (пустой, public/private) и выдаёт **Personal Access Token** (fine-grained: только этот repo, права Contents:Read/Write; или classic со scope `repo`). Токен присылает в чат → я делаю `git init`, `git remote add origin`, `git push` (токен передаю через env `GITHUB_TOKEN=...`, НЕ сохраняю в файлы), затем пользователь токен **отзывает**.
2. Пользователь сам качает папку/zip и заливает (drag&drop в веб-GitHub).
3. Пользователь вставляет этот `MEMORY_AND_PLAN.md` в README репозитория — я в новой сессии «подхвачу» по содержимому.
⚠️ Безопасность: токен = пароль; использовать только в рамках одного действия, потом revoke. Никогда не записывать токен в файлы рабочей папки (исключено из снапшотов, но не рисковать).
